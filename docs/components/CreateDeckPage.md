# CreateDeckPage

**Path:** `src/pages/CreateDeckPage.tsx`
**Route:** `/create-decks` (authenticated, inside [AppLayout](./AppLayout.md))

**Purpose:** Lets a user build a custom deck from the full word list — a two-column "shopping cart" picker (available words on the left, selected words on the right) followed by a naming step, ending with a call to [`create_custom_category`](../rpc-functions/create_custom_category.md). Reached via the "Create Decks" link in [NavBar](./NavBar.md).

**Props:** None — all state is local to the page.

**Layout:** The `Card` has a fixed `h-[75vh]` — the card's overall height never changes with word count, on either side. `CardContent` is `flex-1 min-h-0` so it (and its grid row) fills exactly the space left after the header/footer's own heights; each column is `min-h-0 flex flex-col`, and each scrollable word list is `flex-1 min-h-0 overflow-y-auto` instead of a fixed `max-h-*` — it's the lists that scroll to absorb any amount of content, not the card that grows or shrinks. `min-h-0` is necessary at every level of this chain: flex/grid items default to `min-height: auto` (sized to their content), which silently defeats a fixed-height ancestor by refusing to shrink below content size — without it, a long list would still grow the whole card regardless of the fixed `h-[75vh]`.

**Key behavior:** Fetches the full word list via [useWords](../hooks/useWords.md). `selectedIds: string[]` tracks which word ids have been added; `availableWords` is every word not already selected, filtered by a case-insensitive substring match against a `search` input. Clicking a word in the left column moves its id into `selectedIds` (`handleAdd`); clicking the `X` next to a word in the right column removes it (`handleRemove`) — words move between the two lists rather than being independently toggled, so a word can never appear in both at once. A `Total: {selectedWords.length}` label is `absolute bottom-(--card-spacing) left-(--card-spacing)` within the (`relative`) right column, so it stays pinned to the section's bottom-left corner regardless of how many words are selected or scrolled — flex-flow positioning (`mt-auto`) wasn't enough, since a long selected-words list could still push it out of view. The scrollable list gets `mb-10` (margin, not padding) to reserve that space in layout — padding inside the list's own box wouldn't help, since the box's viewport would still extend into the label's area and mid-scroll items would render underneath it; a margin shortens the box itself so it never reaches that space. The label itself still carries `bg-brand-muted` as a backdrop in case of any rounding-edge overlap. "Total: " is `text-brand-foreground`, the count is `text-brand`.

The card header (title + a one-line usage description) uses `bg-brand-strong`/`text-brand-muted`, separated from the content below by a `border-brand` divider; it's `relative z-10` with a `shadow-lg` so the shadow renders over the content/footer below it rather than being painted over by their opaque backgrounds (`CardContent`/`CardFooter` sit flush against the header via negative margins, so without the stacking order fix the shadow would be invisible). The left/available column uses plain surface styling (`bg-card`); the right/selected column's entire background (not just the scroll box) is `bg-brand-muted`/`text-brand`, applied unconditionally (not toggled by whether any words are selected), separated from the left column by a `border-l border-brand` divider. The footer is `bg-brand-foreground`, and its "Confirm" button uses `bg-success`/`text-primary-foreground` (the same pairing [FlashcardRound](./FlashcardRound.md) uses for its correct-answer state) instead of the default button variant.

Clicking "Confirm" (disabled while `selectedWords` is empty) opens a naming `Dialog` rather than saving immediately, so the deck always has a name before `create_custom_category` is called. Confirming the dialog calls `supabase.rpc('create_custom_category', { p_name: deckName.trim(), p_word_ids: selectedIds })`; on success, navigates to `/my-decks`. On error, shows the RPC's error message inside the dialog instead of closing it, so the user doesn't lose their selection.

# CategoryMenu

**Path:** `src/components/CategoryMenu.tsx`

**Purpose:** Hover-triggered nav dropdown listing flashcard categories (filtered by topic vs. vocabulary-requirement); selecting one navigates to that category's [ModeSelectPage](./ModeSelectPage.md). Its hover mechanics were extracted into [useHoverDropdownMenu](../hooks/useHoverDropdownMenu.md) so the NavBar Admin dropdown could reuse them rather than duplicate them. Rendered twice by [NavBar](./NavBar.md) — once for "Categories" (`vocabulary={false}`), once for "Vocabulary" (`vocabulary={true}`) — the same split the two [SelectDeckCard](./SelectDeckCard.md)s use on the [HomePage](./HomePage.md).

**Props:**

| Prop | Type | Description |
|---|---|---|
| `vocabulary` | `boolean` | `false` = topic categories, `true` = vocabulary-requirement categories. Passed straight through to [`useCategories`](../hooks/useCategories.md). |
| `label` | `string` | Trigger button text ("Categories" / "Vocabulary"). |

**Key behavior:**

- Calls [`useCategories(vocabulary)`](../hooks/useCategories.md) and renders one menu item per category. While the fetch is in flight the menu shows a disabled "Loading..." item; if it resolves with zero rows, a disabled "No categories yet" item. Selecting a category navigates to `/flashcards/standard/:categoryId` — the `standard` segment marks it as a `public.categories` deck, as opposed to a [custom deck](./MyDecksPage.md)'s `/flashcards/custom/:categoryId`.
- The trigger renders its label followed by a Lucide `ChevronDown` icon (`.category-menu-icon`) — static, it does not rotate on open. (The mobile nav sheet's own disclosure chevron, a separate component/file, does rotate on open — see [MobileNavSheet](./MobileNavSheet.md).)
- **Opens on hover, not click.** The open state and hover handlers come from [`useHoverDropdownMenu`](../hooks/useHoverDropdownMenu.md), which is shared with the Admin dropdown in [NavBar](./NavBar.md). The hook's three prop bundles are spread onto the wrapping `<div className="category-menu-group">` (hover enter/leave, with the 200ms close delay that bridges the portal gap), the `DropdownMenuTrigger` (`onPointerDown` preventDefault, so mouse clicks can't fight the hover-driven state), and the `DropdownMenuContent` (`onCloseAutoFocus`, which skips the refocus-on-close only for a hover-driven close). Keyboard activation (Enter/Space) is a separate code path and still opens and closes the menu for keyboard users.
- **`modal={false}`** on the `DropdownMenu` root. Radix's default *modal* menu enables a scroll lock (`react-remove-scroll`) that hides the page scrollbar while a menu is open, which shifts the whole page layout by the scrollbar's width — moving the trigger out from under a stationary cursor, firing a spurious `mouseleave` that closes the menu, which restores the scrollbar and shifts the trigger back under the cursor, reopening it, in a fast loop that reads as flicker. `modal={false}` also skips the modal's focus trap and its `pointer-events: none` on the rest of the page, both appropriate for a hover-driven nav menu rather than a true modal.
- **Trigger hover/open styling** (`.category-menu-trigger:hover, .category-menu-trigger[data-state='open']`): text turns `--brand` color with a 2px `--brand`-colored underline (`text-underline-offset: 6px`, tuned to clear descenders like the "g" in "Categories"). Both selectors share one rule so the trigger stays highlighted for the whole time the menu is open, not just while the cursor is literally over the button — `data-state='open'` reflects the `open` React state (kept alive across the gap-crossing delay above), while `:hover` only matches while the pointer is on the exact element.
- **Item hover/focus styling** (`.category-menu-item`, `.category-menu-item:focus` in `CategoryMenu.css`): background `--brand-muted`, text `--brand`, `font-semibold`. Written as real CSS with Tailwind's `@apply` (same pattern as `.select-deck-button` in [SelectDeckCard.css](./SelectDeckCard.md)), not as inline `focus:` utility classes on the `DropdownMenuItem`, because the underlying Radix primitive already ships `focus:bg-accent focus:text-accent-foreground` — this file's rules need to win that cascade tie, which works because component-level CSS imports land later in the Vite bundle than the base Tailwind layer (the same reason `SelectDeckCard.css`'s `@apply hover:bg-transparent` successfully overrides `Button`'s own `hover:bg-muted`). `:focus`, not `:hover`, is the right selector: Radix menu items move real DOM focus to the item under the pointer on `pointermove`, so `:focus` covers both mouse and keyboard highlighting the same way the base component's own `focus:` classes do.
  - `rounded-none` plus `first:rounded-t-lg last:rounded-b-lg` make the highlighted background a sharp rectangle that still matches the popup's own `rounded-lg` corners on whichever item happens to render first/last (loading state, empty state, or the first/last real category) — Tailwind's `first:`/`last:` variants compile to `:first-child`/`:last-child`, so this needs no index-tracking in the `.map`.
  - `DropdownMenuContent` is given `p-0` (overriding the primitive's default `p-1`) so the highlighted background reaches all four edges of the popup instead of leaving an inset gap; each item's own `px-1.5`/`py-1` (from the base primitive) still keeps the text off the edge.
- **`.category-menu-content`** has a `border-bottom: 2px solid var(--brand)` accent (not a top border) on the dropdown panel itself.

**Implementation notes:** Built on `src/components/ui/dropdown-menu.tsx`, the shadcn wrapper around Radix's `DropdownMenu` primitive (keyboard navigation, focus management and dismissal come from Radix rather than being hand-rolled). The menu panel is widened past its default trigger-matched width with `min-w-48`. Overrides are scoped to this component's own `CategoryMenu.css` rather than edited into the shared `ui/dropdown-menu.tsx` primitive, since that primitive has no other consumer yet and should stay neutral for one that might not want brand-colored hover.

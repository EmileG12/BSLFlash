# NavBar

**Path:** `src/components/NavBar.tsx`

**Purpose:** Top navigation bar rendered on every authenticated page via [AppLayout](./AppLayout.md). Shows the SignStack long-form logo (`/bsl-long-logo.svg`), a "Home" link, the [CategoryMenu](./CategoryMenu.md) dropdowns for Categories and Vocabulary, "Create Decks"/"My Decks"/"Browse Decks" links, and a "Sign Out" button — on screens narrower than the `lg` breakpoint (1024px), these give way to a hamburger trigger opening [MobileNavSheet](./MobileNavSheet.md) instead.

**Props:** None.

**Key behavior:**

- **Responsive split at `lg` (1024px):** the link group (`.hidden.items-center.gap-7.lg:flex` wrapping "Home", both `CategoryMenu`s, "Create Decks", "My Decks", "Browse Decks") and the desktop "Sign Out" button (`hidden ... lg:inline-flex`) are both hidden below `lg` via Tailwind's `hidden`/`lg:` utilities, not conditional rendering — they stay mounted in the DOM at all times, regardless of viewport. A [MobileNavSheet](./MobileNavSheet.md) is always rendered alongside them, below the same `lg` breakpoint. This was deliberate so existing role queries in `NavBar.test.tsx` (expecting exactly one "Categories" button) keep passing unchanged: `MobileNavSheet`'s own duplicate "Categories"/"Vocabulary" controls only render while its sheet is open, so they don't add a second match to those queries at rest.
- **"Sign Out"** calls [`signOut`](../utils/auth.md), then navigates to `/login` regardless of whether `signOut` succeeded or threw (an empty `catch` before the `finally` — sign-out failures are treated as non-blocking, since the user should end up on the login screen either way; without the explicit `catch`, a thrown error would surface as an unhandled promise rejection after the redirect still happened). On desktop it renders as a bordered chip (`.navbar-signout`: `border: 1px solid var(--foreground)`, rounded) with a trailing `LogOut` icon, and hovering it shows the same drop shadow (`box-shadow: 0 8px 12px var(--shadow-color)`) as the deck-select buttons on [SelectDeckCard](./SelectDeckCard.md), reusing the shared `--shadow-color` token. This is a deliberate departure from the plain-underline treatment of the other nav links, not an inconsistency — [MobileNavSheet](./MobileNavSheet.md) gives it an equally distinct (but differently-styled) treatment on its own breakpoint. The border color is `var(--foreground)` rather than a hardcoded black specifically because a hardcoded `#000` is invisible against the near-black `.dark` background.
- **"Categories" and "Vocabulary"** are two instances of [`CategoryMenu`](./CategoryMenu.md), differing only by their `vocabulary` prop — the same split the two `SelectDeckCard`s use on the [HomePage](./HomePage.md). `CategoryMenu` owns its own styling; the hover-dropdown mechanics it shares with the Admin dropdown live in [useHoverDropdownMenu](../hooks/useHoverDropdownMenu.md), and see [CategoryMenu](./CategoryMenu.md) for how it is applied.
- **"Create Decks"** (→ [CreateDeckPage](./CreateDeckPage.md), `/create-decks`), **"My Decks"** (→ [MyDecksPage](./MyDecksPage.md), `/my-decks`) and **"Browse Decks"** (→ [BrowseDecksPage](./BrowseDecksPage.md), `/browse-decks`) are plain `NavLink`s, not `CategoryMenu` dropdowns — each goes straight to a single page rather than listing further choices, so there's nothing to open a menu over.
- **Admin entry (`AdminNavEntry`):** rendered after "Browse Decks" in the link group, and decided by [useUserRoles](../hooks/useUserRoles.md). A plain user sees nothing. Both forms are styled with the `--admin` token (violet) and a leading `Shield` icon, rather than `--brand`: `--brand` already means "current page / primary CTA" on every other item in this bar, so reusing it would make Admin look permanently active; `--warning` means "something needs attention", which an admin area is not. The `Shield` icon is the same in every role tier so the privileged entry reads consistently.
  - An `admin` who is not a superadmin sees a single "Admin" `NavLink` to `/admin`, styled by `.navbar-admin-link` / `.navbar-admin-icon` in `NavBar.css` (structurally the same as `.navbar-brand`, with hover and active color `--admin`).
  - A superadmin sees an "Admin" `DropdownMenu` with five items in three groups: "Add & tag words" (→ [AdminPage](./AdminPage.md)); "Manage categories" and "Manage words"; "Manage roles" and "Manage accounts". The groups are split by two separators. The superadmin pages are documented under [SuperadminCategoriesPage](./SuperadminCategoriesPage.md), [SuperadminWordsPage](./SuperadminWordsPage.md), [SuperadminRolesPage](./SuperadminRolesPage.md) and [SuperadminAccountsPage](./SuperadminAccountsPage.md). The dropdown opens on hover, using the same [useHoverDropdownMenu](../hooks/useHoverDropdownMenu.md) mechanics as `CategoryMenu`, and is styled by `src/components/AdminMenu.css` (`.admin-menu-*` classes, keyed to `--admin`) rather than `NavBar.css`. It uses default content alignment (no `align` prop), so it extends to the right of the trigger like the [CategoryMenu](./CategoryMenu.md) dropdowns do, keeping the nav's dropdowns consistent.
  - The trigger sets `aria-current="page"` whenever the path starts with `/admin` or `/superadmin` (via `useLocation()`), so the underline bar stays lit across every admin and superadmin page, the same way `CategoryMenu`'s trigger marks its active category. `AdminMenu.css` styles this with `.admin-menu-trigger[aria-current='page']::after`, filling the underline with `--admin`.
- The "Home" link turns to `--brand` color with a 2px brand-colored underline on hover (`.navbar-brand:hover` in `NavBar.css`), matching `CategoryMenu`'s trigger hover styling.

**Depends on:** [auth](../utils/auth.md) (`signOut`), [CategoryMenu](./CategoryMenu.md), [MobileNavSheet](./MobileNavSheet.md), [useUserRoles](../hooks/useUserRoles.md) (for `AdminNavEntry`), [useHoverDropdownMenu](../hooks/useHoverDropdownMenu.md) (for `AdminNavEntry`), `react-router-dom` (`Link`, `useNavigate`), `lucide-react` (`LogOut`, `Shield`, `ChevronDown`).

**Tested by:** [docs/tests/NavBar.md](../tests/NavBar.md) (jsdom) and [docs/tests/NavBar.browser.md](../tests/NavBar.browser.md) (real Chromium) — both render `NavBar` and exercise the `CategoryMenu` dropdowns through it.
